# AGENTS.md

Single-binary Rust service (edition 2024): a Rocket 0.5 HTTP API wrapping YouTube search via `innertube-rs`, with the `web/dist/` frontend embedded at build time. Hand-written Rust lives in two source files; `build.rs` generates the asset module. No library target, CI, README, or test suite. The API is a subset of the safe-yt-viewer API (`https://raw.githubusercontent.com/vrandomstuff/safe-yt-viewer/refs/heads/master/API.md`), which the top-of-file notes also point at.

Current state: index -> `search.html` works end to end. `VideoElement.html` links to `/watch.html?v=<id>` and `/channel?c=<id>`; the watch page exists but only loads `${API_BASE_URL}/m3u8/<id>`, and that route is **not implemented** (TODO item 1). There is no channel page at all. Those 404s are expected, not broken markup.

## Commands

- `cargo check` — primary verification and the only real gate. Fast when `target/` is warm.
- `cargo test` — compiles the crate; there is no `#[test]` or `#[cfg(test)]` anywhere.
- `cargo run` — serves on Rocket's default `127.0.0.1:8000`. Ignition pre-warms the Innertube client, so it needs live network access; nothing is mocked or fixture-based, and manual `curl` checks hit real YouTube. The `debug*` routes work only in a debug build (`cargo run`); a release build answers `Only in debug mode`.
- Frontend: `pnpm install` then `pnpm build` in `web/`, then any cargo command to re-embed. `tsc` alone is not enough — `build` also copies `src/**/*.html` and `src/assets/` into `dist/`, then `vendor` copies the Alpine, Tailwind and hls.js browser bundles there. `web/dist/licenses.html` and `web/dist/licenses/` are generated by `build.rs` on the cargo pass, not by `pnpm build`. The scripts use POSIX `cp`, so Windows needs a `cp` on PATH (Git for Windows/coreutils). `web/dist/` is gitignored via `web/.gitignore`, so a fresh clone has no assets until built, and Cargo reruns `build.rs` when `web/dist/`, `web/package.json` or `web/pnpm-lock.yaml` changes.
- `pnpm exec prettier` in `web/` is the TS formatter (`.prettierrc` sets `trailingComma: "none"`; it honors `.editorconfig` tabs) but there is no script and the tree is not fully formatted. Format only files you changed.
- `rustfmt.toml` pins the project conventions (`hard_tabs`, sorted imports, no trailing commas, untouched comments, 160-column `max_width`), so `cargo fmt` would no longer turn tabs into spaces — but the tree has never been formatted with it, so a run still reformats nearly every file. Don't run it as part of unrelated work; treat the config as the target style.
- Ignore `*~` and `#*#` — Emacs backups/locks, not source. (`#README.md#` is an autosave of a README that is not in the tree.)

## Layout

- `build.rs` — regenerates the frontend license page into `web/dist/`, then scans `web/dist/` at compile time and generates `$OUT_DIR/webAssets.rs` (one embedded `#[get]` handler per file plus `fileRoutes()`). License generation is best-effort: missing/failed `pnpm` emits a `cargo:warning` and keeps existing output.
- `web/src/` — plain TypeScript compiled by `tsc` (no bundler), with Alpine.js/Tailwind/hls.js loaded as browser `<script>`s: `api.ts` (response types + `API_BASE_URL`), `search.ts`/`search.html`, `watch.ts`/`watch.html`, `VideoElement.html`, and `alpine.d.ts`/`Hls.d.ts` (the global `window.Alpine` / `window.Hls` typings).
- `src/main.rs` — routes/handlers, cache construction and `.manage(...)`, the global `Innertube` cell, the warmup fairing, the index text, and the `webAssets` module that `include!`s the generated file.
- `src/wrappers.rs` — `Video`/`Channel`/`CORSToken` serde structs, `ytSearch`, `getChannelMetadata`, `searchVideoItemToVideo`, `generateCorsUrl`. Put innertube calls and result flattening here; keep handlers in `main.rs`. It reaches the cache aliases and client through `crate::` (`mod wrappers;` is declared in `main.rs`).
- The struct definitions are duplicated in the index text; update both when a field changes.

## Conventions (non-default — follow these)

- Keep changes scoped to the task. Don't reformat, rename, or "fix" unrelated files, configs, or lockfiles.
- Updating `AGENTS.md` is always allowed and encouraged: record hard-won context here so the next session doesn't rediscover it.
- `.editorconfig` at the repo root is hand-maintained by the repo owner; treat it as read-only unless the task is about it. It sets tabs at width 4, except `*.md` / `*.{yml,yaml}` at 2 spaces. There is no `end_of_line` rule because the tree mixes LF and CRLF (`src/main.rs` LF, `src/wrappers.rs` CRLF); don't mass-normalize line endings.
- TypeScript is `module: nodenext` with `verbatimModuleSyntax`, so relative imports need the `.js` extension (`import { ytSearch } from "./api.js"`) and type-only imports need `import type`. `strict`, `noUncheckedIndexedAccess`, and `exactOptionalPropertyTypes` are all on.
- Alpine is not bundled or imported. `search.html` fetches `VideoElement.html` at runtime into an empty `<template>` and fires `video-template-ready`; `search.ts` waits for that event, clones the template once per hit, calls `Alpine.initTree` on the clone, then assigns `$data(element).videoInfo`.
- The comment block at the top of `src/main.rs` is authoritative for style notes and the ordered TODO roadmap (m3u8 route, web frontend, SponsorBlock, DeArrow; the frontend is in progress). Read it before picking work.
- **Tabs, not spaces**, and **camelCase** identifiers (`apiSearch`, `apiIndex`, `resultPage`, `searchCache`, `Video` fields like `channelAvatar`). `#![allow(nonstandard_style)]` exists specifically to permit this — don't "fix" names to snake_case.
- Rocket is 0.5, but the file intentionally uses `#[macro_use] extern crate rocket;` plus `#[launch]` and `rocket::build()`. Keep that style.
- `rocket` is built with only its default features (`json` is **not** enabled), so handlers serialize with `serde_json::to_string` and return `String`. Don't reach for `rocket::serde::json::Json<T>` unless you also add the `json` feature in `Cargo.toml`.
- Every API route is mounted at `/api/v1`, but the index text (also served under `/api/v1`) lists them as `/api/...`. Keep that style, register every new handler in both its `routes![...]` mount and the index text, and leave the not-yet-implemented `/api/m3u8/...` line in place until the route actually exists. For a breaking change, clone the mount line as `/api/v2` and keep v1 working via wrappers instead of editing v1 in place (the comment on the mount line says exactly this).
- Comment non-obvious library/serde/Rocket usage; the project explicitly asks for it.

## Architecture

- `build.rs` embeds every regular file under `web/dist/` with `include_bytes!`: `index.html` maps to `/`, every other file keeps its relative path, and `fileRoutes()` returns all generated routes as a `Vec<Route>` for `.mount("/", ...)`. Unknown extensions fall back to `application/octet-stream`. Generated asset routes are rejected at build time if they collide with `/health` or `/api/...`, differ only by case, or contain characters unsafe in a Rocket route path; a missing `web/dist` only emits a `cargo:warning` and serves no frontend assets.
- `web/dist` is served verbatim, including `tsc`'s `.d.ts`/`.map` side files. Neither `tsc` nor `pnpm build` cleans `dist`, so output from a deleted or renamed source keeps being served (the tree still carries `main.*` from a deleted `main.ts`) — wipe `dist` before trusting what the binary serves. It is a build artifact, generated licenses included, so never edit it by hand.
- When `web/dist` exists, `build.rs` first runs a Rust port of safe-yt-viewer's `generate_licenses.py`: `pnpm licenses ls --json` in `web/`, copied license texts, and `web/dist/licenses.html` / `web/dist/licenses/LICENSE.*.txt`. `LICENSE_URL_OVERRIDES` currently only maps `alpinejs` to its GitHub license (its package tarball has no license file); `EXTRA_PACKAGES` adds Material Design Icons under Apache-2.0 because it is not a pnpm dependency. Both are retained for future entries. Generated files are embedded on the same pass. pnpm/download/write failures warn (`cargo:warning`) and keep existing output rather than failing the build; files are only rewritten when their content changes to avoid Cargo rebuild loops.
- `innertube()` lazily creates one process-global `Innertube` in a `tokio::sync::OnceCell`; an `AdHoc::on_ignite` fairing pre-warms it at startup. Reuse this accessor; never construct `Innertube::new()` per request.
- `searchCache` is a `moka::future::Cache<(String, u64), Vec<Video>>`: 1-hour TTL, max 5000 entries, keyed by `(query, 1-based page)`. Walking to a deeper page also inserts the intermediate pages it passes.
- `channelCache` is a separate `Cache<String, Channel>`: 24-hour TTL, max 5000 entries. It is filled lazily by `getChannelMetadata` (which calls `get_channel_about`) — both by `/api/v1/channelMetadata` and by the per-video avatar lookups during search, so results and metadata share entries.
- Each search hit triggers a `get_channel_about` for its channel (cached after the first), so a cold page is many sequential upstream calls and feels slow; that is the main cost in `ytSearch`.
- `/api/v1/search` requires both `q` and `page` (`page` is a `u64` capped at 256; `>256` returns 400, missing/non-numeric/out-of-`u64`-range values fail to parse and get Rocket's 422). It follows `continuation_token` from page 1, discards channels/playlists, and returns a JSON array of `Video` (`id`, `thumbnail`, `channel`, `channelAvatar`, `channelName`, `title`). `channel` is the channel ID; `channelName` is the display name.
- `/api/v1/channelMetadata?channelId=...` returns a `Channel` (`id`, `name`, `avatar`, `description`, `banner`); all but `id`/`name` are `Option`. The frontend's `getChannelMetadata()` in `api.ts` still requests `/getChannelMetadata`, which is not the route name — fix the caller if you touch it, not the Rust route.
- `thumbnail` as well as `Channel.avatar`/`banner` are already signed `/api/v1/cors/<token>` paths, not raw YouTube URLs, because the browser loads them through the proxy. `channelAvatar` is such a URL when the channel lookup succeeds and the raw `defaultAvatar` permalink (`yt3.googleusercontent.com/...`) when it fails; it is never empty. The thumbnail is chosen as the largest by area rather than trusting list order.
- The token signing key is 32 random bytes (`getrandom::fill`) generated per process start and only kept in memory, so CORS URLs handed out by a previous run start failing with 401 after a restart (the caches are in memory too). `CORSToken.exp` is epoch **milliseconds**, 6 hours out, because googlevideo URLs expire around then. Debug builds expose `/api/v1/debugGenerateCorsToken?toSign=<url>` (URL-encode the value); it returns the token JSON, which you still base64url-encode without padding to build `/api/v1/cors/<token>` by hand.
- `/api/v1/cors/<token>` echoes the upstream status, headers and body, so it returns the custom `CorsProxyResponse` (`status` + `body` + `Vec<(String, String)>` headers) instead of `Vec<u8>`; its `Responder` impl rebuilds a Rocket `Response` with `set_status` (upstream 4xx/5xx reach the client instead of a 200 error page), `adjoin_raw_header` (keeps duplicates) and `set_sized_body` (recomputes `Content-Length`). `proxySkippedHeaders` drops headers Rocket recomputes, hop-by-hop ones, and anything that would apply *YouTube's* origin policy to ours (CORS/embedding, cookie, `vary`, HSTS/Alt-Svc/pinning, browser policy headers). `content-type`, `content-encoding`, `content-range`/`accept-ranges` and the cache headers are kept on purpose; a missing upstream `content-type` falls back to `application/octet-stream`. Only proxy-level failures use this server's own codes: 400 undecodable token, 401 bad/expired signature, 502 upstream transport error.
- `/health` returns 403 when the `User-Agent` contains `opencode` (via a custom `FromRequest` guard). That is deliberate, not a broken server; don't remove it or the guard to "fix" local testing.
- Error behavior is uniform across the JSON routes: `apiSearch` and `apiGetChannelMetadata` return `Result<String, (Status, String)>`. Upstream/YouTube/innertube failures respond 503 `text/plain`, serialization failures 500. No handler or wrapper unwraps/expects on request or upstream data, so client input cannot panic the server.
- Expensive work logs stderr diagnostics as `[PROFILE]` / `[STARTUP]` lines; follow that pattern for new slow paths.
